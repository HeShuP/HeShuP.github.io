# PAM

Linux PAM (Pluggable Authentication Modules) 是一个系统级用户认证框架。
PAM 将程序开发与认证方式进行分离，程序在运行时调用附加的“认证”模块完成自己的工作。
本地系统管理员通过配置选择要使用哪些认证模块。


# PAM_limits
pam_limits 是 Linux PAM（Pluggable Authentication Modules）框架中的核心模块，负责在用户登录时设置系统资源限制。
这些限制直接影响用户进程能使用的系统资源量，是系统稳定性和安全性的重要保障。

## 核心功能解析
pam_limits 模块通过读取 /etc/security/limits.conf 配置文件，实现以下关键控制：

### 资源限制类型：
```
资源项	控制内容	常用命令
nofile	最大打开文件数	ulimit -n
nproc	最大进程数	ulimit -u
data	数据段内存大小	ulimit -d
stack	堆栈大小	ulimit -s
fsize	最大文件大小	ulimit -f
memlock	锁定内存大小	ulimit -l
cpu	CPU时间（分钟）	ulimit -t
maxlogins	最大并发登录数
```

### 限制级别：

软限制 (soft)：用户可自行修改，但不能超过硬限制

硬限制 (hard)：系统管理员设置，用户不可突破

### 触发时机：

- 用户通过 SSH/TTY 登录时
- su 或 sudo 切换用户时
- 图形界面登录时

```
1. /etc/security/limits.conf
2. /etc/security/limits.d/*.conf  # 推荐修改位置
```

## 配置文件语法示例
/etc/security/limits.conf 格式：

```
conf
# 域        类型    资源项    值
username    hard    nofile    65535
@group      soft    nproc     2048
*           hard    stack     unlimited
```

### 域 (Domain)：

用户名：root

组：@admin

通配符：*（所有用户）

特殊值：%（最大登录数限制）

### 值类型：

数字：1024, 65535

unlimited：无限制

infinity：同 unlimited

## 典型应用场景
### 防止资源耗尽：

```
* hard nproc 5000     # 限制普通用户最多5000进程
@developers soft nofile 100000  # 开发组可打开10万文件
```

### 安全加固：

```
* hard core 0          # 禁止生成core dump文件
* hard maxlogins 3     # 限制并发登录数
```

### 性能优化：

```
oracle soft memlock unlimited
oracle hard memlock unlimited  # 允许Oracle锁定全部内存
```

## 调试与验证方法
### 检查当前限制：

```
登录后查看限制
ulimit -a

查看特定项
ulimit -n -H  # 硬限制打开文件数
```

### 测试配置有效性：

```
# 模拟登录应用限制
sudo -u testuser -i "ulimit -n"
```


### 日志追踪：

```
# 查看PAM日志（系统日志位置）
tail -f /var/log/auth.log | grep pam_limits

# 调试模式（临时）
session required pam_limits.so debug
```


## 常见问题解决方案
### 限制不生效：

- 检查 PAM 配置是否包含：

```
session required pam_limits.so
```

- 确认用户登录方式（SSH需保持 UsePAM yes）

- 避免在 ~/.bashrc 中覆盖 ulimit 设置

### systemd 服务限制

```
# /etc/systemd/system/<service>.d/override.conf
[Service]
LimitNOFILE=100000
LimitNPROC=5000
```

### 容器环境特殊处理：

Docker：使用 --ulimit 参数

```
docker run --ulimit nofile=1024:1024 ...
```

## 技术原理深度
### 内核机制：

- 通过 setrlimit(2) 系统调用实现
- 限制继承自父进程（登录进程→子进程）

### 优先级规则：

```
用户专属设置 > 组设置 > 全局设置(*)
后出现的配置 > 先出现的配置
```

### 与 cgroups 的关系：

- pam_limits：进程级限制（传统 UNIX 机制）
- cgroups：容器级资源隔离（现代 Linux）
- 两者可同时使用形成多层防护


最佳实践：生产环境推荐在 /etc/security/limits.d/ 下创建独立配置文件（如 90-nproc.conf），避免直接修改主文件。
